# tclk/1 conformance material

What is here, where it came from, and what it is not.

## `golden-vectors.json` — official, copied verbatim

| | |
|---|---|
| source | https://github.com/flop-labs/tclk — `tests/vectors.test.ts` |
| commit | `81a83464bd909fb5cd80de647da4e42fbae177dd` (tag `v0.1.0`) |
| retrieved | 2026-09-02T10:20:43Z, by `git clone --depth=50` and reading the file |
| tclk version | `tclk/1` |

These are the reference repository's own anti-drift gate: an offer id, a
contract id, the canonical line each encodes to, and an id for a frame with a
non-ASCII field. `tests/test_tclk.py` asserts this port reproduces every one of
them byte for byte. If a vector ever fails, the port is wrong — a vector is
never edited to make a test pass, which is the reference's rule as well.

One thing was noticed while copying and is recorded rather than resolved: the
vector file says the constants were *generated from the reference
implementation*, while the same repository's `AGENTS.md` says they were
*produced by an independent implementation*. The bytes are the same either way.

## `synthetic-transcript.json` — synthetic, not official

A full deal generated by this port from the project's deterministic **UNSAFE**
test keys (`tests/testkeys.py`): offer, accept, lock, reveal, refund and
receipt frames for one contract, plus five expectations, each giving the frames
to apply, **one instant per frame**, and the status a conforming fold must
reach (claimed; refunded; a replayed accept as a no-op; refund before the
window; reveal after it). `tests/test_tclk.py` reads it back and checks every
expectation, and pins the one `secret` field to the documented test constant
`0x11…11`.

The reference repository publishes no byte-exact end-to-end transcript: its
`examples/htlc-walkthrough.md` says of its own frames that they are "shaped
correctly … but not byte-exact canonical JSON". So nothing here is presented as
an official example beyond the four vectors above.

Why per-frame instants: a transcript replayed entirely at its last frame's
time sees the offer expire before the accept, and folds to `proposed`. That is
the machine being right about the wrong question, and the first version of
this fixture recorded exactly that mistake.

The repository's secret scanner (`scripts/pre_push_check.py`) masks
`0x`-prefixed 64-hex strings under this directory only — tclk ids and
statements are that shape by wire format — and still fires on a bare 64-hex
here or a `0x` one anywhere else. `tests/test_final_gate.py` checks that scope.

## What conformance here does not cover

- The PTLC adaptor-signature cycle (`src/adaptor.ts`). The reference marks it
  unaudited reference cryptography, and this integration does not sign
  anything, so it is neither ported nor tested.
- Any settlement rail, including the reference's `MemoryRail` and `PaperRail`.
- Technocore's own signed-lane verification, which is the existing
  `lineageauth.adapters.technocore` adapter's concern.
